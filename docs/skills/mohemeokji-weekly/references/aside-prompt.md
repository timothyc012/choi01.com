# Aside 일요일 CSV 수집 프롬프트

아래 본문을 Aside의 기존 일요일 작업에 넣는다. 시각은 기존 설정을 유지한다. 이 프롬프트는 별도 예약을 생성하지 않는다. 일요일 9시가 오전이면 09:00, 오후면 21:00인지 예약 화면에서 확인하고 시간대는 Europe/Berlin을 쓴다.

---

모해먹지의 다음 주 식단·장보기에 사용할 독일 마트 할인 데이터를 수집해 주세요.

**대상 주간:** 실행일을 Europe/Berlin 기준으로 계산한 다음 월요일부터 일요일까지. 예: 2026-09-13 일요일 수집이면 2026-09-14~2026-09-20 행사입니다. 수집 날짜와 행사 날짜를 구분하세요. 아직 다음 주 전단이 공개되지 않았으면 지난주 값을 복사하지 말고 해당 매장을 `미공개`로 coverage.csv에 기록하세요. 목요일 시작 행사 등은 품목별 실제 기간으로 기록하세요.

**지역:** 44369 Dortmund, 40468·40474 Düsseldorf, 52062·52064 Aachen. 각 지역의 Netto, EDEKA, REWE, Lidl, ALDI Nord/ALDI SÜD를 확인하되 실제 지점만 기록하세요. 주변 지점이 다른 우편번호에 있으면 실제 우편번호를 사용하고 검색 요청 우편번호를 별도 보존하세요. 같은 체인의 지점이 여러 개이면 지점 ID와 주소로 구분하세요. 거리를 확인하지 않았다면 `최근접`이라고 쓰지 마세요. 이 목록 밖의 신규 실제 우편번호도 누락하지 마세요.

**수집 범위:** 조리에 쓸 수 있는 식품 행사 전체. 육류·생선·달걀·유제품·채소·과일·쌀·파스타·두부·콩류·통조림·빵·기름·소스·양념을 빠뜨리지 마세요. 생닭/익힌 닭/닭가슴살캔, 소고기 부위, 생연어/훈제연어, 모짜렐라/체다/파마산/그릴치즈 등을 구별하세요. 비식품·술·완성된 간편식·과자·음료는 조리 식재료와 구분하고, 정보 부족은 빈칸과 확인 상태로 남기세요. 일반 식품의 가격 미확인을 줄일 수 있다면 해당 지점의 공식 공개 일반가격도 별도 `regular_prices.csv`로 수집하세요. 이것을 할인으로 표시하거나 행사 CSV에 섞지 마세요.

**근거:** 지점을 선택한 마트 공식 행사 페이지·공식 전단을 우선 사용하세요. 일반 홈페이지 URL만으로 가격을 검증했다고 쓰지 마세요. 공식 자료를 열 수 없어 보조 사이트를 이용하면 출처등급을 `보조`로 표시하고 `확인상태=보조출처만`으로 기록하세요. 검색 결과의 짧은 문구만으로 가격을 확정하지 마세요. 필요한 페이지 번호·상품 ID·가격 근거 문구를 남기세요. 사진은 직접 열람 가능한 원문 링크로 충분합니다. 음식 사진을 새로 다운로드할 필요는 없습니다.

**가격 규칙:** EUR 금액은 소수점 두 자리까지, 통화 기호 없이 저장합니다. 일반 행사가격과 앱/쿠폰/회원 가격을 분리하세요. 앱 가격만 확인되면 행사가격은 빈칸입니다. 보증금, 최소 구매 수량, 2+1, 묶음 행사, 구매 한도, 쿠폰 활성화 필요 여부도 기록하세요. `1.99€/100g`는 100g당 가격이지 500g 포장 가격이 아닙니다. 가격적용단위와 실제 포장량을 구별하세요. 상품 옵션에 따라 150g/200g 또는 가격이 다르면 별도 행으로 나누고, 구별할 수 없으면 변형정보·확인상태에 불명확하다고 적으세요. 여러 근거에서 같은 상품을 발견하면 중복 행으로 늘리지 말고 근거만 함께 보관하세요.

**파일 1: supermarket_food_offers_YYYY-MM-DD.csv**

파일명 날짜는 대상 주간의 월요일입니다. UTF-8 CSV, 첫 줄 헤더, 텍스트는 큰따옴표로 감싸고 내부 큰따옴표는 두 번 씁니다. 기존 13개 열을 유지하고 다음 열을 추가하세요. 없는 정보는 추정하지 마세요.

```text
수집시각,체인,지점,우편번호,카테고리,행사기간,상품명,상품정보,행사가격,앱가격,할인율,기준가격,출처,도시,요청우편번호,지점ID,상품ID,변형정보,재료명,상품상태,가격적용단위,포장수량,포장단위,포장개수,총포장량,할인조건,최소구매수량,구매한도,보증금,행사시작일,행사종료일,출처등급,원문근거,근거페이지,확인상태
```

- 수집시각: ISO 8601 + UTC 오프셋, 예 `2026-09-13T09:00:00+02:00`.
- 행사기간: `14.09.2026-19.09.2026`; 시작일·종료일: `2026-09-14`, `2026-09-19`.
- 우편번호: 실제 매장 5자리. 체인명은 `Netto`, `EDEKA`, `REWE`, `Lidl`, `ALDI Nord`, `ALDI SÜD`로 통일.
- 상품상태: 생것/가열완료/냉동/훈제/통조림 등 실제 확인한 상태.
- 가격적용단위: `500 g`, `100 g`, `1 kg`, `1 Stück`처럼 해당 금액으로 살 수 있는 단위. 5봉 전체 가격이면 `5 x 500 g`. 최소 5봉 조건의 봉당 가격이면 `500 g`와 `최소구매수량=5`를 별도로 기록.
- 할인조건: `없음` 또는 실제 조건. 앱/회원/쿠폰/묶음 조건을 숨기지 말 것.
- 기준가격: 이전 판매가격/권장소비자가격(UVP)/kg·L 단위가격을 문구로 구별. 할인율은 출처가 명시했을 때만 기록.
- 원문근거: 상품·중량·가격·기간을 뒷받침하는 짧은 문구. 근거페이지: 전단 페이지 번호 또는 상품별 상세 URL/식별자.
- 확인상태: `공식확인`, `보조출처만`, `가격미확인`, `단위미확인` 중 실제 상태. 미공개 매장은 상품 행을 꾸며 넣지 말고 coverage.csv에만 기록.

**파일 2: coverage.csv**

```text
대상주간,수집시각,요청우편번호,실제우편번호,체인,지점ID,지점,확인한URL,상태,수집상품수,누락이유
```

각 요청 지역·체인별로 `수집완료/일부수집/미공개/접근실패/지점없음`을 기록하세요. 0건과 미확인을 구분하고 다음 주 전단이 공개될 때 다시 확인할 대상을 적어주세요. 상품 수는 중복 제거 후 수로 세세요.

**선택 파일 3: regular_prices.csv**

공식 공개 일반가격을 확인할 수 있을 때만 생성합니다. 쌀·소금·간장·후추·식용유·밀가루·양파·마늘·달걀 등 자주 빠지는 재료부터 조사하고, 상품명/상태/지점/가격적용단위/일반가격/수집시각/출처/근거를 저장하세요. 확보하지 못해도 추정 가격으로 채우지 마세요.

마지막 메시지에는 파일 위치, 대상 주간, 실제 우편번호·매장 수, 수집완료/미공개/실패 목록, 앱 조건 및 단위 미확인 건수, 일반가격 확보 건수를 보고해 주세요. 완전성은 coverage.csv로 설명하고, 접근실패·미공개·불명확 단위는 별도 목록으로 남기세요. 레시피 후보 0건 상품은 이 수집 작업에서 추정하지 않습니다. 이후 `recipe-full` 읽기 전용 후보 조회가 만든 0건 identity 목록을 주간 검증 보고서에 합칩니다. 이 작업은 수집만 담당하며 모해먹지 코드나 레시피 DB를 수정·배포하지 않습니다.
