# 모해먹지와 02Ontology MCP 연결

2026-09-13 실제 연결과 소스를 확인한 제안이다. 아래 신규 도구는 아직 구현하거나 플러그인에 등록하지 않았다.

## 현재 상태

- choi01.com은 CSV → 정확한 상품 형태 매칭 → `01ontology` DB의 `recipe-full` 읽기 전용 검색 → 원본 해시와 한국어 의역 검토 → 불변 주간 스냅샷 순서로 게시한다. 브라우저는 선택한 지점 자료와 필요한 상세만 읽는다. 전체 72,569개 레시피의 실시간 검색 화면은 아니다.
- 연결된 02Ontology는 `personal_search`, `personal_case_get`, `personal_tasks_list`, `personal_source_status`, `personal_activity_list`만 노출한다. `personal_source_status` 실제 호출은 성공했다. 도구가 연결되어 있다는 사실과 식단 기능이 연결되어 있다는 사실은 별개다.
- 02ontology 소스의 `src/onto_packs/recipe/mcp_tools.py`에는 `recipe_store_offers`, `recipe_meal_plan`, `recipe_detail`이 있지만, 소규모 내장 레시피와 캐시가 없을 때 2026년 6월 표본 행사를 쓰는 경로다. 이 도구를 그대로 노출하면 웹사이트와 다른 가격·레시피가 나온다.

## 권장하는 첫 연결

웹과 MCP가 같은 승인 스냅샷과 추천 규칙을 사용하게 한다. 기존 개인 기록 도구를 제공하는 서버에 아래 세 가지 읽기 전용 도구를 별도 등록하고, 현재 연결 프로필의 도구 허용 목록에 이 도구만 추가한다.

| 제안 도구 | 입력 | 반환 |
| --- | --- | --- |
| `meal_locations` | 선택적 `postcode`, `date` | 게시 주, 실제 우편번호·체인·지점 ID, 검토된 행사 수, 메뉴 수, 자료 제한 |
| `meal_recommend` | `postcode`, `store`, `branch_id`, `date`, `mode`, `dietary`, `exclude_ingredients`, `days` | 조건에 맞는 메뉴, 정확히 연결된 독어 할인상품·가격·판매단위·기간, 출처, 추천 이유, 조건 미충족 이유 |
| `meal_recipe_detail` | `snapshot_id`, `source_recipe_id` | 승인된 한국어 재료·수량·순서·저자·원문 링크, 불명확한 수량, 채식 검토 범위 |

서버는 고정된 `https://choi01.com/mohemeokji/data/current.json`을 읽고, 그 안의 manifest 해시와 참조 파일 해시를 검증한다. 경로는 허용된 데이터 루트 아래로 제한하고, 요청마다 선택 지점과 날짜를 검사한다. 새 snapshot ID가 나올 때만 캐시를 교체한다. 해시 검증 실패나 누락을 임의 추정 가격 또는 내장 표본으로 대체하지 않는다.

`meal_recommend`는 웹의 `meal-recommendations.js`와 동일한 순수 추천 로직을 서버에서도 호출할 수 있도록 공통 모듈로 분리해 사용한다. 주재료 할인 필요, 상품 형태, 행사 유효일, 반찬·간식의 자동 식단 제외 규칙을 함께 유지한다. 공개 상세에는 원문 크롤링 본문이나 검토 대기 자료를 포함하지 않는다.

예: “44369 ALDI Nord에서 9월 17일에 살 재료로 채식 저녁 3개 추천해 줘.” 도구는 달걀·유제품 허용 여부를 명시하고, 해당 날짜의 검토된 채식 주메뉴가 3개보다 적으면 실제 개수와 부족한 이유를 반환한다. 반찬을 저녁 메뉴로 바꾸어 개수를 채우지 않는다.

이 첫 연결은 공개된 식단 자료만 읽으므로 개인 이메일 DB를 복사하거나 레시피 전체를 개인 테넌트에 적재할 필요가 없다. 저장 기능이 필요해지면 개인 선호·먹은 기록을 인증된 사용자 범위에 별도로 저장한다. 조회와 기록 저장 도구를 구분한다.

## 전체 원본 레시피 검색을 추가할 때

현재 주간 게시물 밖의 레시피가 필요하면 별도 `meal_recipe_search`를 만들고 레시피 DB에 읽기 전용 권한, 명시적 `recipe-full` 테넌트, 질의·결과 수 제한을 준다. 정확한 할인상품과 원본 재료를 먼저 연결한 뒤 검토 상태와 출처를 반환한다. 검색됐다는 이유만으로 미검토 원문을 공개하거나 게시 승인으로 취급하지 않는다.

영양과 예산 기능에는 별도의 근거 보강이 필요하다. 영양은 식재료별 영양 출처, 가식부 중량, 조리 상태, 분량, kcal·단백질·식이섬유·나트륨이 필요하다. 전체 장바구니 가격이 없는 경우 알려진 소계와 미확인 항목을 나눈다. 채식은 검토한 전체 재료와 선택한 조리안을 기준으로 하며, 비건·알레르기 보증과 동일하지 않다.

## 연결 완료를 확인하는 순서

1. 서버에 새 도구와 엄격한 입력/출력 스키마, `readOnlyHint: true`를 등록한다.
2. 기존 개인용 연결의 좁은 허용 목록에 식단 도구를 추가한다. 전체 개발·관리 도구를 열지 않는다.
3. 서버 재시작 후 MCP `initialize → tools/list → tools/call`로 지점, 만료 날짜, 채식, 영양 근거 부족, 알 수 없는 레시피 ID를 검사한다.
4. 앱의 플러그인 도구 목록을 새로 고침/재연결하고 실제 대화에서 호출한다. 재연결이 필요할 때도 기존 인증 비밀을 문서·저장소·공개 자산에 넣지 않는다.
5. 같은 snapshot ID, 날짜, 지점, 조건에 대해 웹과 MCP의 메뉴 ID·가격·기간이 일치하는지 비교한다.

MCP 서버가 도구를 정의하고 플러그인이 그 연결을 제공하는 구조는 [OpenAI 공식 MCP 서버 문서](https://developers.openai.com/plugins/build/mcp-server)를 따른다. 클라이언트 연결 설정은 [공식 MCP 설정 문서](https://learn.chatgpt.com/docs/extend/mcp)를 참고한다. 여기서 제안한 식단 도구 계약은 이 저장소의 구조에 맞춘 설계이며 OpenAI가 제공하는 내장 도구 이름이 아니다.
